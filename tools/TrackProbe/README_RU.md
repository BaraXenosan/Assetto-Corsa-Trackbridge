# TrackProbe — чтение установленной F1 Manager 2024

Консольная утилита на CUE4Parse. Требуется .NET 10 SDK для сборки. Читает игру, сохраняет результаты только в новую папку. Существующий результат не перезаписывает. Не создаёт и не устанавливает мод.

```powershell
dotnet build .\TrackProbe.csproj
dotnet .\bin\Debug\net10.0\TrackProbe.dll "ПУТЬ_К_Paks" "НОВАЯ_ПАПКА" "ПУТЬ_К_FModel\AppSettings.json" --metadata-only F1Manager24/Content/Circuits/Bahrain/Lvl_Bahrain.umap
```

Вместо `--metadata-only` передайте `--usmap "ПУТЬ_К_СХЕМЕ.usmap"`, чтобы прочитать свойства. Схема должна соответствовать установленной версии игры. После параметров можно перечислить несколько полных путей пакетов из `files.json`.

Утилита использует существующую настройку версии и основного ключа FModel для точно совпадающего каталога игры, а также его локальную библиотеку Oodle. Ключ не сохраняется в отчётах. Рассматриваются контейнеры верхнего уровня; вложенные моды не подключаются. Моды верхнего уровня могут участвовать в разрешении одинаковых путей.

Для автономной проверки переупакованного уровня доступен `--overlay "КАТАЛОГ_ТЕСТОВЫХ_КОНТЕЙНЕРОВ"`. Он явно добавляет `.pak` и `.utoc` этого каталога к оригинальной установке в памяти провайдера, исключая копии `global.*`. Файлы в игру не копируются. Поле `container` в manifest показывает, из какого контейнера действительно прочитан пакет; проверяйте его, чтобы не принять исходный уровень за тестовый. Зависимости по-прежнему берутся из установленной игры.

## Результат

- `files.json`: уникальные пути смонтированных файлов.
- `metadata/`: имена, классы, внешние объекты, таблицы импорта, зависимости и размеры блоков IoStore-пакетов.
- `raw/`: извлечённые байты выбранных пакетов и их payload-файлов.
- `hashes/`: SHA-256 каждого извлечённого файла.
- `properties/`: свойства объектов, только при успешном чтении с настоящей схемой.
- `manifest.json`: режим, версия парсера, использованная схема и ошибки каждого пакета.

Режим metadata-only передаёт пустой контейнер схем исключительно для разрешения чтения заголовков CUE4Parse. Он не вызывает десериализацию свойств и не подставляет выдуманные типы полей. Метаданные не подтверждают семантику гоночных траекторий.

Ошибки чтения свойств считаются фатальными для пакета. Код возврата 2 означает, что хотя бы один пакет не обработан. При ошибке может остаться частичный каталог; для повтора задайте новое имя. Успешная обработка метаданных возвращает 0 и не означает готовность к установке.

Источники API: [CUE4Parse](https://github.com/FabianFG/CUE4Parse), [IoPackage](https://github.com/FabianFG/CUE4Parse/blob/master/CUE4Parse/UE4/Assets/IoPackage.cs), [FileUsmapTypeMappingsProvider](https://github.com/FabianFG/CUE4Parse/blob/master/CUE4Parse/MappingsProvider/Usmap/FileUsmapTypeMappingsProvider.cs). Библиотека подключена через NuGet, её версия закреплена в csproj.
