# RuntimeProbe — чтение живой сессии Bahrain

Использует только `OpenProcess(PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION)` и `ReadProcessMemory`. Не внедряет DLL, не пишет память, не приостанавливает игру и не изменяет файлы игры.

```powershell
dotnet build .\RuntimeProbe.csproj
dotnet .\bin\Debug\net10.0\RuntimeProbe.dll PID EXPECTED_GAME_EXE NEW_OUTPUT_DIRECTORY
```

Требуется процесс из `F1Manager24/Binaries/Win64`, а не launcher. Смещения получены из текущего Dumper-7 SDK для сборки 1.11.0. Перед чтением проверяются полный путь, SHA-256 исполняемого файла и элемент `None` пула имён. При другой сборке чтение прекращается; новые смещения нельзя угадывать.

В `snapshot.json` сохраняются мир, полные пути найденных объектов, 125 узлов RaceSim, корневые позиции CarActor и число ошибок. Бинарные файлы содержат компонент, узлы, их нативные таблицы, известные массивы FTrackPosition и ограниченные структуры машин. Снимок не атомарный: движущиеся машины считываются последовательно. Значения непрочитанных/неподтверждённых полей нельзя трактовать по сходству чисел.

`research/bahrain_live04` — полноценный снимок загруженного Bahrain, 1 рабочая трасса, 22 CarActor, 0 ошибок. `bahrain_live01/02` — более ранние снимки; `table4` в live02 содержит только начальную половину таблиц и не используется при верификации.

`node research/verify-native-spline.js` сопоставляет все полные таблицы с Catmull–Rom и проверяет обратное преобразование дистанций на 55 подготовленных игровых позициях. `car-position-candidates.json` — отдельная неуспешная эвристическая попытка найти FTrackPosition непосредственно в структурах машин; она не служит доказательством.
